# Executive Brief / Problem Intake Note

## Discovery

The top management has requested an learning module in the existing product so the request came after some problems that were faced within the training department and with the clients' final work submission quality issues. So initially the requirement was really heavy with what is needed at the end goal but due to the time restriction and MVP deadline, a lot of scope is deducted.  So the initial requirement included a complete learning training module on the web, which included:

- listing of training modules
- creation of the trainings
- assigning those trainings to the appropriate person
  In the initial requirements the assignment rules for the training were really complex, so that they could be assigned based on location, client, quest, jobs, user, etc.

## Problem Reported

So the reported problem was that with the existing third-party solution that is being used there are two major problems with that:

1. The third-party platform is only on the web without mobile responsiveness or a mobile app.
2. The main issue was that there is no connection between that third-party training software and our own platform, where the actual work is done. This is due to which an employee can actually work on some of the quests which require training prior to completion of that quest. This led to poor quality of the data collected, clients' dissatisfaction, and rework of the same job multiple times to get that quality data.

## Business Goal

So the business goal with this was that creating an learning model within the existing product would:

1. reduce the extra cost of that third-party software
2. streamline the trainings and the work based on those trainings into a single platform
3. the research associate would not have to switch between multiple devices just to perform that work so they can work on the same device and within the same application also

## Proposed Deadline

So the proposed deadline related to this particular learning feature or module was around 8 sprints.
These eight sprints included development, UI testing, and release of the MVP version. 

## Initial Constraints

The initial constraint was the timeline. First of all with a really tight timeline of around 8 sprints, which turns out to be around 4 months' time with a completely new module that does not exist in the current system
The other constraint was that at the initial state we need to have only the must-have things to release the MVP version so that the training can be created and assigned to the field researchers. 

## Pain Point Outlined

So the pain points outlined well this streamlines the effort required to create the training, complete the training, and, based on that training, complete the actual work for the client. This is the pain point that is being solved, which in turn results in good quality data collection for the client.
It solves the problem for three different user types:

- the client
- the management team
- the field associate 

## Target Audience

So this module is basically for our internal team only, which are the field associates or field researchers.
