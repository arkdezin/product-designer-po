# Metrics to Watch

| Metrics Type | What to Measure | Baseline | Target |
| -- | -- |  -- | -- |
| Primary (Success) | New-category product validation success rate | ~65% | ≥82% within first PI post-launch. This is the sharpest pain point and the highest-leverage improvement. |
| Weekly Rework Volume	| Failed products per weekly cycle | 300-450 products/week failing validation | <200 products/week. Measures whether the structured review workflow is catching issues earlier and reducing downstream rework. |
| Velocity	| Time-to-correction for detected errors | 7-day fixed cycle (Mon-Sun) | Active review time within the cycle reduced by ≥40%, enabling same-week correction rather than next-cycle rework. |
| Scalability | AI suggestion acceptance rate | No baseline exists yet. Establish in first 30 days. | ≥55% acceptance rate indicates AI suggestions are trusted and useful — reducing manual override overhead for DM. |
| Guardrail | Overall catalog success rate | 91-94% | Must not decrease. The new workflow must improve quality; it cannot introduce new failure modes that reduce the overall pass rate. |
| Business | Out-of-band flagging volume (email / Teams) | No numeric baseline. | Directional target: measurably fewer ad-hoc data issue communications from Business/Sales at 60 and 90 days post-launch — tracked by sampling communication channels. |
